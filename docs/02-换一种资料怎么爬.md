# 换一种资料，怎么爬？——从「超星作业」引申出去

> 配套文档：`01-这个项目是怎么做出来的.md`（那个是「怎么想到的」，这个是「怎么迁移」）。
> 本文只给路线和方法，不堆代码；所有套路都能用本项目里现成的函数改出来。

---

## 1. 先判断「是哪一类页面」，这决定了一切

拿到一个新目标，别急着写代码，先做**三种三秒判断**：

| 判断 | 怎么做 | 说明什么 |
|---|---|---|
| **要不要登录？** | 用无痕窗口（或 `requests` 不带 Cookie）访问一次 | 302 到 login → 要 Cookie；200 且有内容 → 直接抓 |
| **首屏有没有数据？** | 看 `Ctrl+U` 源码里搜目标文字 | 有 → 服务端渲染，用 XPath 解析；没有 → 数据是 JS 加载的 |
| **有没有接口？** | F12 → **Network** → 过滤 **Fetch/XHR**，刷新，看响应是不是 JSON | 有 JSON → 直接请求接口，比解析 HTML 稳定 10 倍 |

> 记住优先级：**接口 > 静态 HTML > 浏览器自动化**。能用接口就别解析 HTML，能用 HTML 就别开浏览器。

---

## 2. 通用五步法（换任何资料都这么走）

```
① 定位数据位置   —— 接口？HTML？要登录？
② 拿到登录态     —— Cookie（Copy as cURL）/ token / 无
③ 抓一页落盘     —— 存 HTML 或 JSON 原件，之后全靠它调试
④ 切出字段       —— XPath（HTML）或 dict 取键（JSON）
⑤ 循环+存储+核验 —— 翻页、限速、写 Excel/Word/CSV、回读抽样
```

本项目把 ③④ 做到极致，你可以直接抄：

- ③ 的代码：`probe_dowork.py` 里存 HTML + 打结构树 + 数 XPath 命中
- ④ 的代码：`parse_options()` 的「多候选 XPath」思路，任何页面改版都能扛一阵
- ⑤ 的代码：`main()` 的「每条 URL 一个 try/except，失败不中断整体」

## 3. 按资料类型选路线（常见 7 种）

| 你要的资料 | 典型页面 | 推荐路线 | 关键坑 |
|---|---|---|---|
| **题库/作业/试卷** | 超星、各种培训平台 | 静态 HTML + XPath（就是本项目） | 答案在「查看/解析」页才有；选项顺序会打乱 |
| **公告/新闻列表** | 学校官网、政府网站 | HTML 列表 → 详情页循环 | 分页参数（`page=2`）、列表在 iframe 里 |
| **表格数据** | 排行榜、统计数据 | 优先找 JSON 接口；其次 HTML `<table>` → pandas `read_html()` | 表头合并单元格、单位在括号里 |
| **PPT/PDF 课件** | 课程资料、文库站 | 找文件直链（`.pdf` / `.pptx`），`requests` 下载后本地解析 | 直链常带时效签名；PDF 是扫描图就得 OCR |
| **视频** | 课程视频、直播回放 | F12 找 `.m3u8` 或 `.mp4`；m3u8 用 `ffmpeg` 合并 | 加密 m3u8（key）、分片多、耗流量 |
| **图片/图表** | 数据图表、地图 | 找 `img src` 或 canvas 背后的接口 | 懒加载（滚动才请求）、需要 Referer |
| **JS 渲染的 SPA** | 现代前端站 | ①先找 XHR 接口 ②不行再上 Playwright | 别一上来就 Selenium，慢且脆 |

**两个万能判断**：

- 源码里出现 `window.__INITIAL_STATE__` / `__NUXT__` / `__NEXT_DATA__` → 数据被塞在页面里，正则或 `json` 一把就能取，不用开浏览器。
- 页面结构里出现 `<div id="app"></div>` 且源码无内容 → 只能走接口或浏览器自动化。

## 4. 三个高频难题怎么破

### 4.1 分页/翻页

- **URL 参数分页**：`?page=2`、`?pn=20`、`?start=20` → 循环改参数，直到返回空列表
- **接口分页**：POST 里带 `pageNo`/`pageSize`，或返回 `hasMore`/`nextCursor` → 以返回值为准
- **滚动加载**：接口通常带 `offset`/`lastId` → 每次用上一页最后一个 id 续
- **判断结束**：不要靠「没数据就停」的猜测，优先看接口返回的 `total` 或 `hasMore`

### 4.2 加密参数（如本项目的 `enc`、`standardEnc`、`sign`、`token`）

三条路，按性价比排：

1. **不自己算**：直接复制页面请求里的完整 URL（本项目就是这么做的）——时效内一直能用
2. **找源头**：在源码里 `Ctrl+F` 搜参数名，看它是从哪个元素/接口拿的（往往是个隐藏 input）
3. **逆向 JS**：最后手段，找 `md5(...)` / `window.enc` 之类的函数，用 Python 复刻。投入产出比很低，除非长期大量采集

### 4.3 需要登录、且有验证码/风控

- 只抓**你自己有权限看**的内容，用**你自己的账号**
- 控制频率（本项目的 `SLEEP = 1.0` 不是摆设），别并发猛冲
- Cookie 会过期：脚本里判断「被踢到登录页」就明确报错，不要静默失败
- 遇到滑块/点选验证码，**先停手想清楚**：是否必要、是否合规、是否有官方导出功能

## 5. 工具选型（不要过度装备）

| 场景 | 用什么 | 备注 |
|---|---|---|
| 静态 HTML | `requests` + `lxml` | 本项目就这套，够用 90% |
| JSON 接口 | `requests` + 内置 `json` | `r.json()` 直接取 |
| 表格 | `pandas.read_html()` / `openpyxl` | 导出 Excel 一步到位 |
| 文档产出 | `python-docx`（Word）/ `openpyxl`（Excel） | 本项目用了前者 |
| 一定要执行 JS | `playwright` | 比 Selenium 稳；但慢 20~100 倍 |
| 下载大文件/视频 | `requests` 流式下载 + `ffmpeg` | 分段下、断点续传 |

> 判断标准：**如果能在 F12 的 Network 里看到返回纯文本/JSON，就永远不需要浏览器自动化。**

## 6. 把本项目当模板：只改 3 个地方

以「爬某个新闻列表」为例：

```python

URLS = ["https://example.com/news?page=%d" % i for i in range(1, 6)]

# 改动 2：XPath（用 probe_dowork.py 的三招先探出来）
ITEM = "//div[contains(@class,'news-item')]"

LINK  = ".//a/@href"
DATE  = ".//span[contains(@class,'date')]/text()"

# 改动 3：输出（把 write_question 换成写 CSV / Excel）
```

其余部分**原样保留即可**：`build_head()`（Cookie 文件）、`load_from_curl()`（头解析）、`clean()`/`text_of()`（文本清洗）、`dump_struct()`（调试）、`main()` 的 try/except + 限速 + 统计。

一句话：**URLS、XPath、输出**三处换掉，剩下的骨架 90% 都不用动。

## 7. 礼貌与合规（比技术重要）

1. 只抓**你有权访问**的内容；不破解付费/权限内容。
2. `robots.txt`、服务条款先看一眼；个人复习用途与大规模转载是两件事。
3. 限速（≥1 秒/请求）、加重试上限、别在对方服务器高峰期跑。
4. 别把 Cookie/账号共享出去；抓完就删 `curl.txt` 并退出登录（token 就失效了）。
5. 数据里可能含他人隐私（真名、学号、成绩），**不要公开传播**。

## 8. 接下来练什么（学习路线）

| 阶段 | 练习 | 目标 |
|---|---|---|
| 1 | 抓一个**不需要登录**的静态列表页（新闻/豆瓣 Top250），导出 CSV | 掌握 XPath + 循环 + 存文件 |
| 2 | 给它加**分页**（URL 参数或接口 cursor） | 学会判断「什么时候停」 |

| 4 | 找一个 **JSON 接口**站，直接抓接口 | 体会「接口优先」的甜头 |
| 5 | 用 `probe_dowork.py` 的套路，遇到一个**没爬过的站**也能 30 分钟出结构 | 形成方法论 |

**核心心法**（和文档 `01` 结尾那两条一致）：

> 先看见结构（存原件、打树、数命中），再动手写解析；每一步都留证据（报数、抽样、回读）。
